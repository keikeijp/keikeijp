# 投資指標の探索要領 (indicator_lab の設計メモ)

参考: [【追加記事】シストレのススメ 3.5.投資指標の探索要領 — これからの「お金」の話をしよう](https://we.love-profit.com/entry/2018/04/01/152750)

上の記事の考え方を、コードで機械的にチェックできる形に落としたものが `indicator_lab` です。
AI (Claude など) に売買戦略を考えさせるときも、このメモを前提として渡すと、
「バックテストで儲かって見えるだけの戦略」を出しにくくなります。

## 基本の考え方

- 投資指標 = 売買判断の基準 (例: 15 日移動平均乖離率が -10% でロング)。
  指標 1 つにつき、計算期間と閾値のようにパラメータが 2 個以上付く。
- 採用する指標は 1〜3 個に絞る。パラメータが増えるほどカーブフィッティングしやすい (AIC の考え方)。
- 指標の良し悪しは **情報係数 IC = 指標とリターンの相関** で測る。
  期待リターンはおおよそ `E[r | Z] ≈ IC × σr × Z`。
  - `σr`: リターンの標準偏差 (ハイリスク・ハイリターン)
  - `Z`: 指標の raw 値を時系列で正規化したスコア (いまが普段からどれだけ外れているか = 収益機会)
- 目安は |IC| ≥ 0.05 で「優秀」、≥ 0.1 で「非常に優秀」。
  ただし IC が小さいほど偶然である確率 (p 値) が上がり、無効な指標を採用しやすくなる (第一種の過誤)。

## チェックリスト

| # | 確認すること | indicator_lab |
|---|---|---|
| 1 | まず散布図を描き、近似直線・決定係数・信頼区間を見る | `information_coefficient` (IC, rank IC, 95% CI, R²) |
| 2 | 無効な指標で「たまたま平均が高い区間」を切り出していないか | `binned_expectation` (区間ごとの件数と t 値) |
| 3 | IC だけで判断せず、時系列の累積リターンを見る。特定期間だけ効く指標を避ける | `zscore_strategy`, `subperiod_ic` → `sign_stability` |
| 4 | 分位別 (5〜10 グループ) のリターンが階段状か | `quantile_returns` → `monotonicity` |
| 5 | 指標とリターンの分布が正規分布から大きく外れていないか | `distribution_report` → `non_normal`、順位相関 `rank_ic` を主に使う |
| 6 | たくさん試した分だけ判定を厳しくする (データ・スヌーピング対策) | `screen` の `q_value` (Benjamini-Hochberg) |
| 7 | 「なぜ効くのか」を演繹的に説明できるか。相関でなく因果を考える | **人 (または Claude) が説明を書く**。自動化しない |
| 8 | 条件付きで効く指標 (交互作用) を探す。ただしレジームもパラメータ | `regime_ic` |
| 9 | 特徴選択には単純な手法を使う | `lasso_select` (LassoCV + 時系列 CV), `extra_trees_importance` (深さ 2) |

## リターンの取り方

- リターンは売買したい時間軸での一定期間の騰落率 (`forward_returns(close, horizon)`)。
  エントリー指標は「エントリー直後の値動き」を予測できれば十分。
- イグジット専用の指標は基本的に使わない。期待リターンが 0 になったら手仕舞えばよく、
  指標 B でイグジットしたいなら、B でエントリーする戦略を並行して走らせればよい。
- `horizon > 1` のリターンは期間が重なり観測が独立でないので、
  実効サンプル数を `n / horizon` として p 値・信頼区間を計算している。

## このツールが追加でやっていること

記事の範囲を超えて、実運用で問題になりやすい点を補っています。

- Z スコアはローリング窓で計算する (全期間の平均・標準偏差を使うと未来の情報が混ざる)。
- 資産曲線に取引コスト (`--cost`) を入れられる。
- `candidate` は |IC| ≥ 0.05、q 値 ≤ 0.05、分位の単調性 ≥ 0.8、符号の安定性 ≥ 0.8 をすべて満たすもの。
  合成データでは、本物の指標だけが残りノイズ 20 本は落ちることをテストで確認している。

## 使い方

```bash
pip install -e ".[indicator]"

# 答えの分かっている合成データで動作確認
indicator-lab demo --select

# 自分のデータ (Date, Close 列 + 自作指標の列) を評価
indicator-lab screen prices.csv --horizon 5 --cost 0.0005 --select
```

`candidate=True` になっても、それは「統計的に否定できなかった」だけです。
採用前に 7 番 (なぜ効くのか) を必ず確認し、最後はフォワード運用で小さく試してください。
